## 一、这份文档是什么

这是一份**单一美国公司的基础财务系统**的完整需求，符合美国通用会计准则（US GAAP）和美国常见的合规做法。

它有三个特点：

1. **与实现无关**：不提任何平台、语言、数据库或架构。UBOS 和你的 Java 系统用同一份需求实现。
2. **可验收**：每条需求都有具体的验收标准；大部分验收标准直接引用示例公司的数据和金额。
3. **可对比**：自带一个示例公司的数据集、自动算出的预期结果、共用的验收场景和对比协议。两套系统按同一把尺子打分。

软件不销售，目标是做出一套专业、完整、可用于演示的基础财务系统，不考虑市场差异化。

## 三、范围

**包含**：
- 总账与科目表；
- 带审批的凭证、定期凭证、自动冲回凭证；
- 会计期间、月结、年结、受控的重新开账；
- 应收（发票、贷项通知单、收款核销、对账单、账龄、坏账）；
- 应付（供应商、W-9 税号、账单审批、防重复、付款批次、ACH 与支票文件、1099 报送）；
- 银行（对账单导入、自动匹配、银行对账、转账、正向支付文件）；
- 固定资产（登记、直线法和双倍余额递减法折旧、处置）；
- 多币种（ASC 830 期末重估、已实现和未实现汇兑损益）；
- 基本州销售税（按目的地计税、免税证书、申报数据）；
- 四张财务报表及钻取、"按当时所知"报表；
- 内控、审计轨迹、访问安全、记录保存。

**不包含**：
- 工资计算（工资结果只作为汇总凭证导入）；
- 存货与成本、采购订单、合并报表与多公司；
- 预算、项目核算、复杂收入确认（ASC 606）、租赁（ASC 842）、所得税申报。

## 五、示例公司 Northwind Components, Inc.

**公司设定**：
- 虚构的特拉华州 C 类公司，总部在德州奥斯汀，自然年会计年度，本位币美元，另有欧元客户；
- 36 个科目、4 个客户（德州、俄勒冈、德州转售商、德国）、8 家供应商（其中 3 家需报 1099）、3 项固定资产；
- 期初日期为 2025-12-31，数据包含 2026 年 1 月全部业务和 2 月的几笔业务。

**已确认的参数（2026-09-29）**：
- 2026 年 1099-NEC/MISC 报送门槛：2,000 美元；
- 奥斯汀合并销售税率：8.25%。

**数据怎么用**：
1. 两套系统都通过**自己的界面或 API** 逐笔录入业务，不直接导入分录。
2. 税额、折旧、汇兑损益、所得税等计算结果由系统自己算，再与预期结果比对。
3. 预期结果由脚本 `docs/finance-requirements/tools/gen_finance_expected.py` 用十进制精确计算，并自动做勾稽检查：
   - 借贷平衡、资产等于负债加权益；
   - 现金流量表与现金变动一致；
   - 账龄合计等于控制科目；
   - 银行对账差额为零。

## 七、两套系统怎么比

**五条原则**：
1. 同一版需求（git 标签）；
2. 同一套预期结果做裁判，由非开发人员执行验收；
3. 工作量随做随记，不事后估算；
4. 范围差异逐条登记；
5. 不把预期结果手工录进系统。

**14 个指标**，包括：
- 总工时和各领域工时、周期、代码量和配置量；
- 无需写通用代码就能满足的需求占比；
- 缺陷率、首次验收的预期结果不符数；
- 标准变更的前置时间和工时；
- 性能、可用性得分、审计支持时间、运维工时。

**6 个标准变更请求**，在首次验收后两边依次实现：
- 降低审批阈值并增加第二审批人；
- 新增一个州的销售税；
- 新增"部门"维度；
- 修改资产使用年限并新增 150% 余额递减法；
- 客户早付折扣；
- 更正历史汇率。

对比报告把"首次开发"和"后续变更"分开统计。UBOS 的优势预计主要体现在变更、审计支持和正确性上。
