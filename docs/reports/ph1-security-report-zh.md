# PH-1 安全报告（第 19d 步）

本报告汇总 PH-1 已有的安全验证证据，供 gate 1b 验收（第 20 步）使用。范围是退出标准
EXIT-1-10（L2 沙箱逃逸）和 EXIT-1-16（租户隔离、密钥卫生、安全事件覆盖），以及相关的认证、
授权、加密和隐私结果。

本报告只汇总已运行的验证，不是新的漏洞排查或安全审查（CLAUDE.md 第 4 条）。外部渗透测试
（SUITE-NOD-PEN）按计划在 PH-2 进行。英文证据见各报告目录，日期 2026-10-18。

## 1. 结论

| 退出标准 | 结果 | 证据 |
|---|---|---|
| EXIT-1-10 L2 沙箱逃逸 ≥300 例 100% 拦截 | **382/382 拦截**，达成 | `verify/reports/exit-1-10/` |
| EXIT-1-16 隔离套件 100% 通过 | **544/544**，0 次跨租户访问，达成 | `verify/reports/exit-1-16/` |
| EXIT-1-16 密钥扫描 0 命中 | **0 命中**（6 类来源，127,459 字节），达成 | 同上 |
| EXIT-1-16 安全事件 100% 覆盖 | **28/28** 种 PH-1 事件类型，安全日志哈希链校验通过，达成 | 同上 |

两项安全退出标准在工作站和 CI 上都已达成。参考环境（ENV-REF-SMALL）上的复跑待租用后进行。

但有一个**未达成的安全基线**，必须在对外部署前处理：**传输加密（TLS）**。
详见第 4 节。按 DEC-087，它已移到 PH-2 第 11 步（CR-SOC2-003、NR-SEC-004）。

## 3. 验证过程中发现并已修复的问题

| 步骤 | 问题 | 修复 |
|---|---|---|
| 19a | 会话键是顺序编号，且任何调用方都能使用别人的会话键 | 改为随机 `sess-<32 位十六进制>`，并绑定到调用方指定的租户 |
| 19a | 全节点运维接口（诊断、健康、遥测、配置）任何租户的管理员都能调用 | 只允许运维租户（节点默认租户）调用，其他租户返回 `IAM.DENIED` |
| 19a | 分支授权策略对 UBTP 请求不生效（UBTP 绑定没有传主体） | UBTP 的读、查询、历史、时间线、原始提交和版本化请求都带上会话主体 |
| 19c | 授权读取用 `commit` 选择器，每行都要加载整个分支（性能问题，可被放大成拒绝服务） | 改用提交序号；查询结果改为一次批量读取（行已被同一主体的行过滤器授权） |

## 4. 遗留事项与风险（按优先级）

1. **传输加密（TLS 1.3）缺失（高）**
   - 现状：PH-1 Server 只监听明文 HTTP/WebSocket，安装包也没有终止 TLS 的反向代理。`server.tls_certificate` 目前只用于证书到期检查。
   - 影响：NR-SEC-004、CR-SOC2-003 未达成。在工作站以外部署前必须解决。
   - 决定（DEC-087）：CR-SOC2-003、NR-SEC-004 移到 PH-2 第 11 步（随高可用 Server）。约束：在工作站以外的任何部署之前必须完成。
2. **外部渗透测试（中）**：SUITE-NOD-PEN 计划在 PH-2 进行，供应商按 DEC-085 在第 19 步前安排。
3. **WebAuthn 第二因子推迟（中）**：随 Web 工作区在 PH-2 提供（DEC-075）。PH-1 用 TOTP。
4. **生产发布密钥（中）**：创世 Buk 目前用开发发布者密钥签名。生产密钥随发布流程建立。BPA 标准标签 `bpa-v1.0.0-rc1…rc7` 待您签名。
5. **隐私控制推迟（中）**：
   - 默认屏蔽个人字段（DSN-DVM-821）、个人数据读取日志（DSN-DVM-823）、更正前版本的主体密钥加密（DSN-DVM-830）都在 PH-2（DEC-086）。
   - PH-1 的数据不应含真实个人数据。
6. **流程读取整个分支（中，可用性）**：大分支上一次端口调用可达数分钟（30 万对象 287 秒），可被用作资源耗尽手段（19c 发现）。按 DEC-087 在 PH-2 第 0b 步修复。
7. **数据库连接预算（低，可用性）**：节点的连接数随打开的 VAE 增长，参考环境需要设连接预算或连接池代理（15e、19b 观察）。
8. **FIPS 140-3 认证模块（低）**：NR-SEC-004 的目标之一，PH-1 未处理。
