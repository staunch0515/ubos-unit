## 3. Open questions

| ID | Question | Status |
|---|---|---|
| OQ-001 | PH-1 carries 341 requirements (kernel breadth). Should PH-1 be split into PH-1a (store, model, versioning, transactions, logic) and PH-1b (rules, flow basics, events, IAM, proofs), each with its own exit gate? | Resolved by DEC-014 |
| OQ-002 | The first vertical covers fund operations and contracts in PH-2. Should either be deferred to PH-3 to shorten PH-2? | Resolved by DEC-015 |
| OQ-003 | Hosted Cell (PH-4) comes after Server (PH-1/PH-2). Is on-premises/private-cloud Server the confirmed first commercial form? | Resolved by DEC-016 |
| OQ-004 | STD-TIME-011 `set_period` rejects an intersecting segment "not fully covered by a segment of the same version lineage", but "version lineage" is not defined. The PH-0 model (`verify/models/timeline.tla`) reads it conservatively: reject when an existing segment intersects `[a, b)` without lying inside it. Under that reading `set_period` can never split a segment; it only fills gaps or replaces whole segments. Is that intended, and how is "version lineage" defined? | Resolved by DEC-032 |
| OQ-005 | STD-VER-040 builds a virtual merge base "by recursively merging" several best common ancestors in ascending `commit_id` order, but does not say which base each recursive merge uses or how conflicts inside the virtual merge are resolved. The PH-0 model (`verify/models/merge.tla`) uses the recursive base of the ancestors merged so far, keeps the base value for conflicting fields, and unites ledger entries by `entry_id`. Should the clause adopt this rule? | Resolved by DEC-032 |
| OQ-006 | STD-VER-013 lists the branch kinds `release`, `draft`, `feature`, `agent`, `overlay`, `loader`, `evolution`, `correction`, `sandbox`, `device`, while DSN-DVM-206 lists `main`, `work`, `release`, `correction`, `simulation`, `agent`, `device`, `import`. The standard takes precedence (UBS-META-05 §4), and BPA 0.1 vectors use STD-VER-013. Should DSN-DVM-206 be aligned with STD-VER-013? | Resolved by DEC-032 (addendum) |
| OQ-007 | STD-CTX-020 says the L2 string length, array and map sizes "follow the profile", but STD-CTX-004 lists no such sizes. The PH-0 spike uses 1 MiB strings and 65,536 elements for `strict`, scaled ×8 for `standard` and `agent`, ×64 for `batch`, ×128 for `simulation`, plus 1,024 variables, 256 functions, 64 KiB source and expression depth 64/32 (DEC-034). Should STD-CTX-004 adopt these values? | Resolved by DEC-036 |
| OQ-008 | Rhai's `decimal` type is a 96-bit, 28-digit decimal, while L1 expressions use the arbitrary-precision decimal of `ubos-types`; results differ beyond 28 digits and large values overflow in L2 only (DEC-034). Should the kernel decimal be registered as the L2 decimal type, or L1 decimals be bounded to the same range? | Resolved by DEC-036 |
