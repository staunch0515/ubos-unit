# Instructions `run.*` and `emit.*`

> BPA 1.0.0-rc9. Generated by `standard/tools/build_release.py` from `docs/50-system/30-standard/10-instruction-set/02-run-emit.md`; do not edit. Clauses outside this release are omitted.

### STD-ISA-050 — `run.port`
- **Clause:** Invokes a port on an object or class, synchronously within the current process (shared unit of work, STD-TXN-002).

  | Aspect | Value |
  |---|---|
  | Params | `target: uri`, `port: text`, `params: map` |
  | Result | the port's result type |
  | Errors | the port's declared errors, plus `MODEL.PORT_NOT_IMPLEMENTED`, `FLOW.PORT_UNAVAILABLE`, `FLOW.GUARD_FAILED`, `RULE.DECISION_DENIED`, `RULE.DECISION_REQUIRES`, `IAM.DENIED` |
  | Determinism | as the port's implementation |
  | Cost | 20 plus the callee's consumption (shared budget) |
  | Authorization | the port's `permission` |

  Decisions returning `require` MUST raise `RULE.DECISION_REQUIRES` with the list of required steps. The caller may catch it only to report. It MUST NOT be converted into success.

  A port implementation names `<asset>#<function>`; the function sees the target as `this` and its identifier as `self_id` (DEC-044).
- **Grammar / Schema:** —
- **Conformance vectors:** VER-CONF-3400…3429
- **Satisfies:** FR-MODEL-031, FR-FLOW-022, FR-RULE-051
- **Notes:** Nesting depth is limited by the profile (default 32). Since 1.0-rc3 (DEC-071): before the implementation runs, in this order, the port must be available in the object's lifecycle state (`states` of the declaration, and the transition it names must leave the state; `FLOW.PORT_UNAVAILABLE` with `{port, state}`), the permission is checked, the decisions of a command port are evaluated (STD-LGS-031), and the port's `guards` — L1 booleans over `this`, `params` and `ctx` given as text — are evaluated, every failing one reported in `FLOW.GUARD_FAILED` `{port, failed: [{guard}]}`; the guards evaluated are recorded in the rule binding of the commit (STD-TIME-040).

### STD-ISA-053 — `run.decision`
- **Clause:** Evaluates a decision table (FR-RULE-041) with typed inputs and returns its outputs under the table's hit policy. The table version is recorded in the rule binding.

  | Aspect | Value |
  |---|---|
  | Params | `table: uri`, `inputs: map`, `asof: date?` (default: process `asof`) |
  | Errors | `RULE.NO_MATCH` (policy `unique` or `first` without a match), `RULE.MULTIPLE_MATCH` (`unique`) |
  | Determinism | `snapshot` |
  | Cost | 10 + 1 per row evaluated |
  | Authorization | `evaluate` on the table |
- **Grammar / Schema:** —
- **Conformance vectors:** VER-CONF-3450…3469
- **Satisfies:** FR-RULE-041, FR-RULE-043
- **Notes:** Since 1.0-rc8 (DEC-091): the table is evaluated as in STD-LGS-040, in its version valid at `asof`, and the result is its `outputs`; the versions of the tables a process evaluated are listed in the `tables` member of the rule binding of its commit (STD-TIME-040). An unknown table is `IAM.NOT_FOUND`.

### STD-ISA-054 — `run.validate`
- **Clause:** Evaluates validations, invariants and commit-point declarations for proposed changes without committing, and returns all findings (the validation preview).

  | Aspect | Value |
  |---|---|
  | Params | `changes: list<change>` or `target: uri` (for current unit-of-work changes) |
  | Result | `{violations: list<explanation>, warnings: list<explanation>}` |
  | Determinism | `snapshot` |
  | Cost | 20 plus the evaluation work |
  | Authorization | `read` on the targets |
- **Grammar / Schema:** —
- **Conformance vectors:** VER-CONF-3470…3479
- **Satisfies:** FR-RULE-035, FR-AI-045
- **Notes:** Since 1.0-rc2 (DEC-067): one of `changes` and `target` is given; with `target`, the changes of the current unit of work on that object are previewed. The preview does not stop the process: a unit of work with error-level violations still fails at its commit.

### STD-ISA-071 — `emit.notify`
- **Clause:** Requests a notification from a template to recipients (principals, roles or relations) after commit. Rendering happens per recipient with that recipient's permissions (FR-NTF-012).

  | Aspect | Value |
  |---|---|
  | Params | `template: uri`, `subject: uri`, `recipients: list`, `channels: list?`, `priority: enum?`, `action: port-ref?` (for Action Messages) |
  | Result | `{notification_id}` |
  | Determinism | `deferred` |
  | Cost | 20 + 2 per recipient |
  | Authorization | `notify` on the subject |
- **Grammar / Schema:** —
- **Conformance vectors:** VER-CONF-3515…3524
- **Satisfies:** FR-NTF-011, FR-OFFICE-061
- **Notes:** Since 1.0-rc8 (DEC-094):
  - **Templates.** A template is an object of the genesis class `NotificationTemplate` with `title` and `body`; `{{this.<field>}}` placeholders take the subject's values.
  - **Recipients.** Recipients are DIDs, `role:<name>` (the principals of the adapter's directory with that role, operation `principal`) or `relation:<name>` (the principals the subject's relation reaches, STD-LGS-050); other forms fail with `MODEL.INVALID_VALUE`.
  - **Rendering.** After commit, each recipient and channel gets an effect `notification` with `{notification_id, recipient, channel, priority, title, body, action}`, rendered with the recipient's clearances and masks (STD-LGS-052); hidden fields render empty. A process that fails sends nothing.
  - **Defaults.** `channels` defaults to `in_app`, and `priority` to `normal` (`low`, `normal`, `high`).
